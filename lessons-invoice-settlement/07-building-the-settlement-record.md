# Lesson 07 — Build the Settlement Record in LedgerLane

This workflow turns operational tasks into a reviewable settlement schedule.

## 1. Prepare projects and engagements

Attach each task to the correct project. Define the engagement as one-time, retainer, barter, or community partnership and record the agreed amount or non-cash description. Select only the projects belonging to the settlement cycle.

## 2. Curate invoice lines

Open a task and use **On the invoice** to:

- include or exclude it;
- set a client-facing name;
- assign a parent line;
- enter billable hours;
- identify the billing period; and
- attach up to three named evidence links from the task form.

The report's edit mode also lets an editor add lines, add sub-lines, include an excluded board task, edit names/periods/hours, add evidence, and remove a line from the invoice. A newly created invoice line is still a task in the selected project's first column, so give it a meaningful owner and status.

## 3. Review the report lens

In **Reports → Invoice settlement**, choose the included projects. Check every row, not only completed tasks: the invoice lens includes all task statuses unless explicitly excluded. Confirm owner, period, hours, evidence, and amount.

Parent rows display hours rolled up from their immediate sub-lines. Because both parent and sub-lines remain visible, separately test totals and presentation for double counting. The amount column shows a task's settlement amount when present and “Ready” otherwise.

## 4. Review engagement totals

LedgerLane separates task-derived totals from engagement-derived totals. A project with a settled engagement is excluded from task-total accumulation to reduce duplicate charging. A barter or community partnership with no cash amount can display as a non-cash settlement record. Validate these behaviors against the actual agreement; software logic does not replace contractual review.

## 5. Add cover context

Use report notes for explanatory context such as the contract reference, billing period, assumptions, or acceptance statement. Evidence that supports a specific deliverable belongs on that line, not only in a cover note.

## 6. Export and issue

Use **Download CSV** for row-level reconciliation and **Print** for the sheet presentation. Before sending externally, transfer or supplement the schedule in the approved invoicing system with required invoice metadata such as legal names, unique invoice number, issue/due dates, currency, tax identifiers and breakdown, purchase-order reference, remittance instructions, and total amount due.

## 7. Freeze the issued version

Store the issued PDF/CSV, timestamp, recipient, and delivery method. Subsequent edits in the live app should not obscure what the customer received. Corrections should create a traceable revision or credit process.
